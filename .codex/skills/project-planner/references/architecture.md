# 技术架构指南

用于创建 `docs/technical-architecture.md` 或规划中的技术架构章节。

## 推荐结构

1. 架构目标
2. 系统总览
3. 前端架构
4. 后端架构
5. 数据模型
6. API 设计
7. 认证与权限
8. 第三方集成
9. 部署与环境
10. 测试策略
11. 可观测性
12. 安全与隐私
13. 性能与扩展性
14. 关键风险和技术决策

## 架构细节清单

尽量明确：

- 运行时、框架、语言和包管理器
- 目录和模块划分
- 主要组件及职责
- 数据实体、字段和关系
- API 路由或服务方法
- 状态管理方式
- 后台任务、队列、定时任务或事件流
- 必要的缓存策略
- 必要的文件或媒体存储策略
- 环境变量和密钥管理方式
- 本地开发方式
- 部署目标和构建流程

## 技术决策记录

重要选择建议写清：

- 决策
- 原因
- 考虑过的替代方案
- 取舍
- 未来什么条件下应该重新评估
