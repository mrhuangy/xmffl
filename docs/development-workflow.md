# 微信记忆翻牌消除小游戏开发流程

## 目标

本文档用于指导项目从空仓库进入可开发状态，并按 `technical-architecture.md` 中的 Cocos Creator + TypeScript + 微信小游戏架构逐步实现首页、关卡选择、关卡页、核心翻牌逻辑、存档、广告和发布流程。

当前阶段先不做静态页面原型，直接按微信小游戏正式开发路线推进。

## 开发阶段总览

| 阶段 | 目标 | 主要产物 | 验收标准 |
| --- | --- | --- | --- |
| 0. 环境准备 | 建好开发工具和项目基础 | Cocos 项目、微信开发者工具配置 | 能在 Cocos 预览空场景 |
| 1. 工程结构搭建 | 建立代码和资源目录边界 | `src/`、`assets/`、场景、配置、服务目录 | 目录符合技术架构，能正常编译 |
| 2. 基础场景搭建 | 搭首页、关卡选择、关卡页骨架 | `HomeScene`、`LevelSelectScene`、`GameScene` | 场景之间能跳转 |
| 3. 核心玩法实现 | 实现翻牌、匹配、消除、失败/通关 | `CardGrid`、`CardView`、`MatchSystem` | 2x2 和 4x4 关卡可完整游玩 |
| 4. 进度和奖励 | 保存关卡、星级、金币、提示 | `ProgressService`、`RewardService` | 重启后进度不丢失 |
| 5. UI 和资源还原 | 按效果图做视觉和动效 | 首页、关卡选择、关卡页 UI | 主要界面接近效果图 |
| 6. 广告和数据 | 接入激励视频、广告事件 | `AdService`、`AnalyticsService` | 测试广告流程完整 |
| 7. 微信发布准备 | 构建、真机、体验版、审核 | 微信小游戏包体 | 体验版可试玩 |

## 阶段 0：环境准备

### 工具准备

- 安装 Cocos Creator 3.x。
- 安装微信开发者工具。
- 准备微信小游戏 AppID；没有正式 AppID 时先用测试号或游客模式调试。
- 确认本地 Node.js 和 npm 可用，用于依赖、脚本和工具链。

### 仓库准备

建议在当前仓库根目录创建 Cocos 项目，不另开仓库。项目创建后保留现有 `docs/` 作为策划和技术文档目录。

推荐根目录结构：

```text
assets/                   Cocos 资源目录
  scenes/
  textures/
  prefabs/
  audio/
src/                      TypeScript 业务代码
  scenes/
  components/
  systems/
  services/
  configs/
  models/
  utils/
docs/                     项目文档
settings/                 Cocos 项目设置
package.json
tsconfig.json
```

### 验收

- Cocos Creator 能打开当前项目。
- 能创建并运行一个空场景。
- 微信开发者工具能导入 Cocos 构建后的小游戏目录。

## 阶段 1：工程结构搭建

### 目录和职责

| 目录 | 职责 |
| --- | --- |
| `src/scenes/` | 场景控制脚本，例如首页、关卡选择、游戏主场景 |
| `src/components/` | 可挂载到节点的 UI 和表现组件 |
| `src/systems/` | 纯玩法系统，例如匹配系统、关卡管理 |
| `src/services/` | 存档、奖励、广告、数据等服务 |
| `src/configs/` | 本地关卡配置、广告频控配置、主题配置 |
| `src/models/` | 类型定义和枚举 |
| `src/utils/` | 洗牌、时间格式化、本地存储适配 |
| `assets/scenes/` | Cocos 场景文件 |
| `assets/prefabs/` | 卡牌、按钮、弹窗等预制体 |
| `assets/textures/` | 背景、动物牌面、按钮、图标 |

### 第一批类型文件

先定义基础模型，再开发系统：

- `GameState`
- `CardState`
- `CardConfig`
- `RuntimeCard`
- `LevelConfig`
- `LevelResult`
- `PlayerProgress`
- `AdEvent`

### 验收

- 项目能编译通过。
- 每个模块目录有明确职责。
- 不在 UI 脚本里直接写洗牌、存档、广告奖励等核心逻辑。

## 阶段 2：基础场景搭建

### 场景列表

| 场景 | 文件建议 | 说明 |
| --- | --- | --- |
| 首页 | `HomeScene.scene` | 展示玩家信息、资源、开始游戏、关卡选择入口 |
| 关卡选择 | `LevelSelectScene.scene` | 展示普通关卡和锁定状态 |
| 游戏关卡 | `GameScene.scene` | 核心翻牌消除玩法 |

### 场景跳转流程

```text
HomeScene
  -> Start Game -> GameScene(currentLevel)
  -> Level Select -> LevelSelectScene

LevelSelectScene
  -> Back -> HomeScene
  -> Select Unlocked Level -> GameScene(levelId)

GameScene
  -> Complete -> ResultPanel
  -> Next Level -> GameScene(nextLevelId)
  -> Back/Home -> HomeScene
```

### 验收

- 首页点击“开始游戏”能进入当前关卡。
- 首页点击“关卡选择”能进入关卡选择。
- 关卡选择页点击已解锁关卡能进入对应关卡。
- 游戏页返回按钮能回到首页或关卡选择。

## 阶段 3：核心玩法实现

### 开发顺序

1. `LevelManager`：读取关卡配置，返回当前关卡。
2. `CardGrid`：根据 `rows`、`cols`、`pairCount` 创建卡牌节点。
3. `shuffle()`：生成两两成对的牌组并随机打乱。
4. `CardView`：实现背面、正面、消除三种表现。
5. `MatchSystem`：控制翻牌状态机。
6. `GameScene`：连接 UI、牌阵、计时、失败次数和结算。

### 必须实现的规则

- 每关开始后先正面展示 `initialPreviewMs`，默认 2000 毫秒。
- 开局预览期间不允许点击卡牌，不计入用时。
- 每次最多翻开两张牌。
- 两张牌 `pairId` 相同则消除。
- 两张牌 `pairId` 不同则错配次数 +1，并在 `flipBackDelayMs` 后盖回。
- 超过 `levelTimeLimitSeconds` 判定失败。
- 错配次数超过 `maxMismatchCount` 判定失败。
- 全部卡牌消除判定通关。

### 关卡配置建议

第一批先配置 20 关：

| 关卡段 | 牌阵 | 配对数 | 时长 | 错配上限 | 目的 |
| --- | --- | --- | --- | --- | --- |
| 1-2 | 2x2 | 2 对 | 45 秒 | 6 次 | 新手学习 |
| 3-5 | 3x4 | 6 对 | 90 秒 | 10 次 | 过渡难度 |
| 6-20 | 4x4 | 8 对 | 120 秒 | 12 次 | 标准体验 |

### 验收

- 固定牌组下，匹配和错配结果正确。
- 预览期间点击无效。
- 错配次数达到上限后进入失败。
- 时间耗尽后进入失败。
- 全部消除后进入通关结算。

## 阶段 4：进度、星级和奖励

### `ProgressService`

职责：

- 保存当前关卡。
- 保存每关最高星级。
- 保存金币、提示道具数量。
- 保存设置项，例如音效、震动。

第一期使用微信本地存储 API；在浏览器或 Cocos 预览环境下可用本地适配器兜底。

### `RewardService`

职责：

- 根据关卡结果计算星级。
- 发放通关金币。
- 发放广告奖励。
- 对广告奖励做 `rewardId` 去重。

### 验收

- 通关后当前关卡推进到下一关。
- 已通关关卡可在关卡选择页看到星级。
- 重启游戏后金币和关卡进度仍然存在。

## 阶段 5：UI 和资源还原

### 资源使用

效果图和资源位于 `docs/pic/`，开发时建议迁移或复制到 Cocos 资源目录：

```text
assets/textures/backgrounds/
assets/textures/icons/
assets/textures/cards/
assets/textures/ui/
```

迁移原则：

- 背景图单独作为场景背景。
- 首页、关卡、关卡选择页共用森林卡通风格。
- 动物牌面从拼图资源裁切为单张卡牌图片。
- 按钮和图标优先做成可复用预制体。

### UI 实现顺序

1. 首页顶部资源栏。
2. 首页主按钮和侧边入口。
3. 底部导航栏。
4. 关卡选择标题、标签页、关卡卡片网格。
5. 游戏页顶部状态栏。
6. 游戏页卡牌棋盘。
7. 底部道具按钮。
8. 通关、失败、暂停、提示弹窗。

### 验收

- 首页布局接近 `首页效果图.png`。
- 关卡选择布局接近 `选择关卡效果图.png`。
- 游戏关卡布局接近 `关卡效果图.png`。
- 小屏和高屏手机不遮挡主要按钮和棋盘。

## 阶段 6：广告和数据

### 广告接入顺序

1. 先实现 `AdService` 空实现，保证业务代码不依赖微信广告 API。
2. 在微信环境下接入激励视频。
3. 接入“看视频拿提示”。
4. 接入“通关奖励翻倍”。
5. 接入“失败复活”。
6. 最后再接插屏广告频控。

### 广告奖励规则

- 广告完成才发奖励。
- 广告关闭或失败不发奖励。
- 同一 `rewardId` 只能发放一次。
- 局内翻牌过程中不弹强制广告。
- 插屏只在关卡间自然间隙出现。

### 数据事件

| 事件 | 时机 |
| --- | --- |
| `level_start` | 进入关卡并结束预览后 |
| `level_complete` | 通关结算 |
| `level_failed` | 超时或错配次数超限 |
| `ad_requested` | 玩家点击广告入口 |
| `ad_completed` | 激励视频完整观看 |
| `reward_granted` | 奖励发放成功 |

### 验收

- 测试广告完成后奖励发放。
- 关闭广告不发奖励。
- 广告失败时能回到原界面。
- 事件日志能区分关卡、广告位和奖励来源。

## 阶段 7：微信小游戏构建和发布

### 本地构建

在 Cocos Creator 中选择微信小游戏构建目标，输出到构建目录。构建参数建议：

- 平台：微信小游戏。
- 方向：竖屏。
- 资源压缩：开启。
- 首包资源：只放首页、基础 UI、前几关必要资源。
- 远程资源：后续主题和大量牌面可考虑远程化。

### 微信开发者工具验证

验证清单：

- 启动无报错。
- 首页、关卡选择、关卡页可进入。
- 真机触摸区域正常。
- 本地存储可读写。
- 广告测试位回调正常。
- 包体大小符合微信小游戏要求。

### 体验版流程

1. 使用测试广告位构建体验版。
2. 内部试玩 20-30 分钟。
3. 记录新手关是否理解、是否频繁失败。
4. 调整时长、错配上限和星级阈值。
5. 替换正式广告位。
6. 提交审核。

## 推荐开发任务拆分

### 第 1 周：可玩核心

| 任务 | 说明 |
| --- | --- |
| 初始化 Cocos 项目 | 建场景、目录、脚本结构 |
| 实现关卡配置 | 先做 1-20 关本地配置 |
| 实现牌组生成 | 两两成对、随机打乱 |
| 实现翻牌匹配 | 预览、翻牌、匹配、消除、盖回 |
| 实现失败和通关 | 超时、错配上限、全部消除 |

### 第 2 周：界面和存档

| 任务 | 说明 |
| --- | --- |
| 首页 UI | 按效果图实现主入口 |
| 关卡选择 UI | 关卡卡片、星级、锁定 |
| 游戏页 UI | 状态栏、棋盘、道具按钮 |
| 结算弹窗 | 通关、失败、重玩、下一关 |
| 本地存档 | 当前关卡、星级、金币、提示 |

### 第 3 周：广告和打磨

| 任务 | 说明 |
| --- | --- |
| 激励视频提示 | 看广告获得提示 |
| 双倍奖励 | 通关结算广告翻倍 |
| 失败复活 | 后续挑战模式复活入口 |
| 数据事件 | 关卡和广告事件记录 |
| 真机优化 | 适配、性能、触摸、音效 |

## 每日开发检查清单

- 核心玩法是否还能跑通 3 个关卡。
- 是否有场景脚本直接修改存档或广告奖励。
- 新增 UI 是否适配小屏和高屏。
- 新增配置是否有默认值。
- 失败、重开、返回、广告关闭是否会造成状态卡死。
- 改动玩法后是否同步更新 `docs/gameplay-design.md`。
- 改动架构后是否同步更新 `docs/technical-architecture.md`。

## 风险控制

| 风险 | 控制方式 |
| --- | --- |
| UI 先行导致玩法不稳 | 先完成 `MatchSystem` 和固定牌组验证 |
| 状态机混乱 | 所有点击都先检查 `GameState` |
| 资源过大 | 先裁切和压缩图片，后续考虑远程资源 |
| 广告回调重复 | 奖励必须通过 `rewardId` 去重 |
| 存档结构变化 | 给存档加 `version` 字段，升级时兼容 |
| 难度过高 | 前 5 关降低牌数、时长更宽松、错配上限更高 |

## 开发完成定义

第一版 MVP 完成需要满足：

- 首页、关卡选择、游戏关卡、结算弹窗可用。
- 第 1-20 关可配置、可进入、可保存进度。
- 第 1-2 关为 2x2 新手关，第 3-5 关过渡，第 6 关后进入 4x4 标准关。
- 开局 2 秒正面预览正确。
- 超时和错配次数超限会失败。
- 全部卡牌消除会通关。
- 本地保存金币、提示、当前关卡和星级。
- 激励视频广告至少支持提示和双倍奖励两个广告位。
